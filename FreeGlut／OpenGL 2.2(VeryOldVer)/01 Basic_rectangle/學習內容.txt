LOpenGL.h
    預先將library include進來
    當我們需要在程式碼中包含 OpenGL 標頭時，我們將包含此標頭。透過將 OpenGL 標頭封裝在該檔案中，
    我們可以輕鬆地將 OpenGL 程式碼移植到其他視窗系統，例如 SDL、Qt、GTK 等，這些系統都有自己的 OpenGL 標頭。

LUtil.h
    LUtil.h 和 LUtil.cpp 是我們用來保存初始化和主循環函數的實用程式原始檔
    包含 OpenGL 標頭後，我們定義螢幕寬度/高度以及每秒的螢幕幀數。
    現在讓我們聲明一些函數。首先我們宣告 initGL() 來初始化圖形庫。在每個函數聲明下，您將看到前置條件、後置條件和副作用。現在不要太執著於這些言論。
    對於那些不熟悉前置條件、後置條件和副作用的人，這裡有一些簡單的定義：
        Pre Condition: 呼叫函數之前必須滿足的條件
        Post Condition: 呼叫函數後，結果為真
        Side Effects: 函數在類別之外所做的任何更改

LUtil.cpp
    bool initGL()
        初始化函數的實際程式碼      
        初始化矩陣
        函數的先決條件是有效的 OpenGL 上下文處於活動狀態。 OpenGL 上下文保存 OpenGL 資訊（紋理、著色器、狀態機變數等），以便我們可以開始進行 OpenGL 呼叫。
        在 main() 中，我們將在呼叫此函數之前使用 freeGLUT 建立一個具有 OpenGL 上下文的 OpenGL 視窗。

        初始化矩陣後，我們使用 glClearColor() 將目前透明顏色設為黑色。第一個參數是紅色，第二個是綠色，第三個是藍色，最後一個是 alpha。
        清除顏色是呼叫 glClear() 清除螢幕時螢幕填滿的顏色。與顏色資料通常的 0 到 255 整數值不同，glClearColor() 使用 0 到 1 浮點值進行著色。

        矩陣和透明顏色初始化後，我們使用 glGetError() 檢查是否有任何錯誤。如果發生錯誤，我們使用 gluErrorString() 將錯誤寫入控制台。 
        GLU（OpenGL 實用程式）為我們提供了不屬於 OpenGL 標準的有用函數。在這種情況下，glGetError() 會傳回一個整數錯誤代碼，
        而 gluErrorString() 將該錯誤代碼轉換為 C 字串，以便我們列印到控制台。

    void render() 
        這是我們的渲染函數的開始。在開始繪製之前，我們使用 glClear() 清除顏色緩衝區，並使用 glClearColor() 設定顏色。
        顏色緩衝區幾乎就是繪製到螢幕上的像素。還有其他緩衝區，例如深度緩衝區和模板緩衝區

        螢幕清空後，呼叫 glBegin() 開始繪製四邊形。現在我們可以透過發送頂點開始渲染四邊形。
        頂點是定義幾何形狀的點，在本例中是四邊形的角點。我們發送每個角點並將它們連接起來
        頂點順序很重要，可以按順時針或逆時針順序發送四邊形的頂點，但以任何其他順序都會得到奇怪的結果。

        btw,順逆時針可以表示 現在看到的面是正面還反面 可以利用這個進行優化

        我們使用 glVertex() 將頂點傳送到 GPU（圖形處理單元），第一個參數是 x 座標，第二個參數是 y 座標。
        由於 OpenGL 在這裡是作為 C API 實現的，且C不支援函數重載，因此許多 OpenGL 函數根據它們接受的參數具有不同的命名版本。
        如果你想傳送三維頂點，你可以呼叫 glVertex 3f ( 3 f loats )。

        發送完向量座標後，我們呼叫 glEnd() 來指定我們已完成傳送頂點並渲染四邊形。
        注意：如果我們想在這裡渲染2個四邊形，我們不需要再呼叫glBegin()和glEnd()。
        我們只需呼叫一次 glBegin()，傳送 8 個頂點（4 個頂點 * 2 個四邊形），然後呼叫一次 glEnd() 即可讓它一次渲染 2 個四邊形。

        在 render() 函數的末尾，我們使用 glutSwapBuffers() 更新畫面。
        在此應用程式中，我們將使用雙緩衝視窗。這意味著我們有兩個緩衝區，前緩衝區和後緩衝區。
        前端緩衝區是使用者看到的。後台緩衝區位於記憶體中。當我們在雙緩衝視窗中進行渲染呼叫時，它們會被渲染到後台緩衝區。
        渲染完想要向使用者顯示的內容後，我們將前緩衝區與後緩衝區交換，以便使用者看到我們最初渲染到後緩衝區的內容。
        
        在單一緩衝視窗中，所有內容都直接繪製到前緩衝區。這意味著用戶將在渲染時看到幾何圖形，這意味著他們可能會看到未完成的渲染和撕裂。
